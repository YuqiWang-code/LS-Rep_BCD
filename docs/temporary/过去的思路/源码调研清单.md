# 源码调研清单

核验日期：2026-09-11。对象：全监督遥感二值变化检测，固定 A2Net-LWGANet-L0 主路径，第一阶段仅使用离线 SAMStruct 与 DINOv2 派生 OVCDistill。

本文以你提供的 `参考文献_TeacherRouting.txt` 中 16 篇全文的方法、公式与算法为判断依据，并核对公开仓库目录及下列实际函数；项目接入判断参考服务器/Cache 说明、`下一阶段方向调研.md` 和当前 GitHub 的 `AGENTS.md`、模型、数据加载与训练代码。**“论文提出”“公开代码实现”“本项目需要补写”分别标明，未把仓库首页等同于完整开源，也未运行这些论文的训练实验。** 下列源码链接指向本次核验的默认分支，后续可能更新。

## 1. 结论先行：最少需要读哪几篇源码

**最少读 2 篇源码：UNIC（ECCV 2024）＋ U-Know-DiffPAN（CVPR 2025）；建议再读 1 篇：Segment Any Change（NeurIPS 2024）。** UNIC 提供最贴近你需求的“逐 teacher、逐样本 loss → 选择系数 → 聚合”骨架，以及可删除的异构对齐头；U-Know-DiffPAN 提供实际可查的“离线输出/不确定性/特征缓存 → 学生训练 → 可靠性加权 loss”链路；Segment Any Change 用来厘清 SAM 的单时相分割质量与二时相变化证据，避免把高质量实例边界直接视为可靠变化监督。这里的“最少”是针对当前方案的源码阅读建议，不是运行你方法必须安装的依赖数。

**另外 13 篇只读论文即可：BAN、ChangeCLIP、SemiCD-VL、BFD、CKCD、GoodSAM、CLIP-KD、AM-RADIO、Mask-CDKD、CLearning、DynaKD、MTKD-RL、Re-DTS。** 其中 MTKD-RL 与 Re-DTS 必须认真比较方法边界，但你已排除 RL，无需阅读或移植它们的策略梯度训练代码；GoodSAM、BFD 的官方仓库本次均只有 README，不能开出不存在的模块清单；Re-DTS 所属 Re-MTKD 仓库公开的是测试代码，未找到其路由训练实现。

| 你的环节 | 最少源码阅读来源 | 阅读之后仍须自己实现的部分 |
|---|---|---|
| 诊断：构造六维困难画像 | 当前项目预测/GT 接口；16 篇中没有可直接搬用的完整实现 | 边界漏检、内部碎裂、小变化漏检、背景误报的定义、归一化和空区域处理 |
| 评估：区分质量 q 与适配度 d | U-Know-DiffPAN 的不确定性加权；建议补看 AnyChange 的变化证据 | 困难区域上的 teacher 可靠性、与当前学生需要的匹配，及其校准/监督目标 |
| 路由：逐样本多教师权重 | UNIC 的逐教师 loss 和聚合接口 | 输入 h、q、d 的两层 MLP；它不是 UNIC 原有的 teacher dropping |
| Reject：教师损失严格归零 | UNIC 的选择系数与 U-Know 的损失分项，主要读它们的限制 | K+1 动作、全部教师分项统一门控、避免全 Reject 的训练目标 |
| 训练后全部删除 | UNIC 的 expendable projector；当前项目 `switch_to_deploy()` | 保持主预测及训练协议一致，删除 router、评估器、辅助头及相关状态 |

**不需要再找一个 RL/Agent 仓库来获得两层 MLP。真正缺失的是 d 的可检验含义与 router 的学习目标，不是 `Linear → ReLU → Linear → Softmax` 的写法。**

## 2. 逐篇源码清单（按优先级排序）

### P0-1｜UNIC：必须读，负责“异构损失分开算，再按样本路由”的骨架

- **论文**：*UNIC: Universal Classification Models via Multi-teacher Distillation*，ECCV 2024。
- **源码**：[naver/unic](https://github.com/naver/unic)，**官方代码，已核验实现文件**；[作者项目页](https://europe.naverlabs.com/unic)。
- **论文定位**：方法中的教师特征标准化、expendable/ladder projectors、Teacher Dropping；与下面的实际实现一起读。

| 要读的文件 / 函数 | 代码实际做什么 | 解决你的哪个具体问题 |
|---|---|---|
| [`modeling/losses.py`](https://github.com/naver/unic/blob/main/modeling/losses.py)：`loss_per_teacher()`、`unic_loss()` | 各 teacher 的输出分别对齐、计算损失，保留每个样本的 loss，再交给聚合器 | **路由前的损失接口**：SAMStruct 与 OVCDistill 不应先混成一个 teacher target，也不应先把 batch 平均成标量再乘样本权重 |
| [`modeling/teacher_dropping.py`](https://github.com/naver/unic/blob/main/modeling/teacher_dropping.py)：`aggregate_losses()`、`_get_teacher_coefficients_by_loss()` | 按样本生成 teacher 系数，保留最大 loss 对应教师，其余随机丢弃；系数停止梯度后乘教师损失 | **路由 / Reject 的接入点**：把固定随机规则替换为自己的 MLP 输出，并明确修改“至少一个教师”的限制 |
| [`modeling/unic.py`](https://github.com/naver/unic/blob/main/modeling/unic.py)：`LP`、`AdaptMLP`；必要时看 `load_student_encoder_from_checkpoint()` | 为不同教师建立独立投影头；部署/迁移可只取 encoder | **异构监督与部署删除**：按 teacher 的输出类型建立训练专用头，不改 A2Net 主 decoder |
| [`teachers/__init__.py`](https://github.com/naver/unic/blob/main/teachers/__init__.py)：`get_teacher_output()`；[`main_unic.py`](https://github.com/naver/unic/blob/main/main_unic.py)：`train_one_epoch()` 中 teacher 前向到 `backward()` 的片段 | 教师输出在 `no_grad` 下生成、标准化，学生前向和投影头保留梯度 | **stop-gradient**：分清冻结的 teacher / 状态统计，与仍需训练的 student / adapter |

**可直接借鉴：** 以 teacher 名称组织输出与损失字典；先形成 `[B,K]` 损失矩阵；教师专用训练头；教师输出与选择统计的梯度隔离。无需搬整个 ViT、CLS-token 蒸馏和多层 ladder。

**必须改造的四处：**

1. **不要沿用“最大蒸馏 loss 的 teacher 必须保留”。** 这代表学生尚未拟合该 teacher，不代表该 teacher 对 GT 正确，更不代表它能修复当前 CD 困难；在已出现负迁移的项目里，这个保底规则尤其不合适。
2. **改掉 Reject 不兼容的约束。** `aggregate_losses()` 明确断言每个样本至少保留一个 teacher，而你必须允许一个也不用。
3. **重新定义归一化。** 该函数实际用 `coeffs.sum()` 对整个系数矩阵归一化，不能仅凭注释认定是“每个样本等权”；你的路由应沿 teacher 维度处理，再按 batch 平均，且不能把 Reject 留出的概率质量又归一化回 teacher。
4. **按输出语义改 loss，不能把全部 Cache 当通用特征。** SAM 的实例 ID 不是可做 MSE/cosine 的连续向量；OV 的 `soft_change` 是变化响应；`relation` 需要先确认定义。借用的是损失组织方式，不是所有分支统一 cosine＋Smooth-L1。

**读到什么程度就停：** 能画出“各 teacher 独立头 → 各自 `[B]` loss → `[B,K]` 系数 → batch loss”的张量流，且能指出系数何处 detach、何处不允许全零，就已解决本项目需要的源码问题。

### P0-2｜U-Know-DiffPAN：必须读，负责“可靠性影响哪一项监督”和离线 Cache 训练

- **论文**：*U-Know-DiffPAN: An Uncertainty-aware Knowledge Distillation Diffusion Framework with Details Enhancement for PAN-Sharpening*，CVPR 2025。
- **源码**：[KAIST-VICLab/U-Know-DiffPAN](https://github.com/KAIST-VICLab/U-Know-DiffPAN)，**官方代码，已核验训练、缓存与 loss 文件**；[作者项目页](https://kaist-viclab.github.io/U-Know-DiffPAN-site/)。
- **论文定位**：不确定性建模及学生蒸馏，特别是 Eq. (17)–(19) 的 hard / soft / feature 三项。

| 要读的文件 / 函数 | 代码实际做什么 | 解决你的哪个具体问题 |
|---|---|---|
| [`utils/loss_utils.py`](https://github.com/KAIST-VICLab/U-Know-DiffPAN/blob/main/utils/loss_utils.py)：`kd_loss()`、`KD_Loss.forward()` | hard loss 用 `1 + teacher_variance`，soft loss 用 `1 - teacher_variance`，另有独立的 feature loss | **评估 / Reject**：可靠性应作用于哪些监督项；拒绝教师时为什么不能只屏蔽 soft response |
| [`S1_FSA_T_pretrain_save.py`](https://github.com/KAIST-VICLab/U-Know-DiffPAN/blob/main/S1_FSA_T_pretrain_save.py)：`S1_pretrain_save()`、`save_to_h5()` | 在无梯度阶段保存 teacher 输出、`var_map` 与多层特征，保存前 detach 并移到 CPU | **离线化**：教师推理与学生训练解耦；一个样本的响应、可靠性和特征共同索引 |
| [`dataset/pan_dataset_for_dist.py`](https://github.com/KAIST-VICLab/U-Know-DiffPAN/blob/main/dataset/pan_dataset_for_dist.py)：`PanDataset.get_divided_dist()`、`aug_trans()`、`__getitem__()` | 从蒸馏缓存取对应数据，对图像、GT 和 teacher 字段同步几何增强 | **可靠性与空间对齐**：q、教师目标与困难区域必须处于同一坐标系 |
| [`S2_FSA_S_train.py`](https://github.com/KAIST-VICLab/U-Know-DiffPAN/blob/main/S2_FSA_S_train.py)：`train_FSA_S()` 中读取 `sr/var_map/dist_feat`、调用 `criterion_kd` 的片段 | 训练循环读取固定 teacher 数据，学生输出与其计算蒸馏损失后反传 | **训练循环**：两类 Cache、GT 主损失、辅助损失如何在学生一步更新中衔接 |

**可直接借鉴：** 缓存字段一起读取、一起变换、一起传给 loss；显式分开 GT、输出蒸馏与特征蒸馏；教师不确定性与学生困难分别处理。

**必须改造：**

- 原文是 **PAN-sharpening、单 teacher、连续图像重建**，其 learned variance 不是你的学生预测熵，也不是 SAM quality 或 OV confidence 的同义词。不能直接令 `teacher_variance = 1 - cache_confidence` 就声称完成可靠性建模。
- 原文的方向是“不确定性高时更依赖 GT、低时更依赖 teacher”，不是“越难越加大 teacher 蒸馏”；你的方案要求 GT 监督保持，因此只借教师分项的可靠性门控思想，不复制其 GT 重加权。
- **已核验的 `kd_loss()` 直接使用 `1 - teacher_variance`，函数中没有裁剪或概率校准。** Teacher 的 `models/FSA_T.py` 以 SoftPlus 产生 variance，SoftPlus 本身不保证上界为 1；因此不能把此实现当作对任意置信度都安全的非负权重模板。是否实际越界需查其真实 Cache，本文没有据此断言原实验出现负权重。
- feature loss 不随上述 soft-response 权重归零。你的 Reject 必须同时关掉 boundary、instance/region、soft-change、relation，以及任何 teacher 诱导的 adapter loss。
- 原函数最终直接 `.mean()`；需改为先保留像素/区域维度完成可靠性加权，再得到每个样本、每个 teacher 的 loss，交给 UNIC 式聚合接口。

**不需要读：** 扩散采样器、频率选择注意力、PAN 专用网络。缓存生成脚本只读数据与梯度生命周期，不需要重跑，更不应把新的 diffusion teacher 加入 Pool。

### P1-3｜Segment Any Change：建议读，负责“结构可信”到“变化相关”的边界

- **论文**：*Segment Any Change*，NeurIPS 2024。
- **源码**：[Z-Zheng/pytorch-change-models](https://github.com/Z-Zheng/pytorch-change-models)，**作者维护的官方实现所在仓库**，不是另造的 `SegmentAnyChange` 仓库名。
- **论文定位**：Bitemporal Latent Matching，以及单时相 proposals 到双时相变化掩码的生成过程。

| 要读的文件 / 函数 | 代码实际做什么 | 解决你的哪个具体问题 |
|---|---|---|
| [`torchange/models/segment_any_change/anychange.py`](https://github.com/Z-Zheng/pytorch-change-models/blob/main/torchange/models/segment_any_change/anychange.py)：`AnyChange.bitemporal_match()`，包括内部 `_latent_match()` | 同一 proposal 的空间 mask 分别池化两时相 embedding，负 cosine similarity 构成变化分数；同时处理两时相提出的 masks | **评估中的 d**：SAM 对某处“分割得好”与该处“发生变化”是两个问题；变化证据须来自两时相的对应空间支持 |
| [`torchange/models/segment_any_change/simple_maskgen.py`](https://github.com/Z-Zheng/pytorch-change-models/blob/main/torchange/models/segment_any_change/simple_maskgen.py)：`SimpleMaskGenerator._process_batch()` | 分别用 predicted IoU、stability score 筛选分割 masks | **q 的含义**：mask quality 是分割可信度，不能直接作为变化正确率 |
| [`torchange/models/segment_any_change/base.py`](https://github.com/Z-Zheng/pytorch-change-models/blob/main/torchange/models/segment_any_change/base.py)：`SegmentAnyChange.proposal()`、`forward()`、`set_cached_embedding()` | 组织双时相 proposals、embedding 缓存、匹配和后处理 | **二时相接口**：检查双向覆盖、字段流向，以及“缓存 embedding”和你现有“缓存结构 map”的区别 |

**可直接借鉴：** 两时相对称地使用结构证据；把 `quality` 与 `change_confidence` 分开；用空间区域对应关系比较两时相，而不是比较实例编号。

**必须改造 / 不可直接运行的原因：** AnyChange 使用 SAM 的 dense embeddings，并含 SAM 特定的特征变换；现有 SAMStruct 只有 instance/boundary/quality，不能重现该 latent matching。它也不是 SAM2 的现成蒸馏器。第一阶段既然沿用已验证格式的 Cache，就把它作为 d 的设计检查，不为复现它擅自重建缓存。你可以在训练 GT 定义的困难区域上评价两时相结构证据的适用性，但这部分是自己的方法。

**不需要读：** 单点/多点交互提示和可视化分支；它们不解决你的全监督、离线路由需求。

- OV `soft_change` 如何由两时相特征构造；`confidence` 如何融合 `photometric_confidence`；`relation` 的 8 个通道各代表什么、顺序如何、取值范围是什么。
- SAM `quality` 的具体生成/聚合方法，以及实例重叠处理与 boundary 生成的先后关系。

你的文档已明确：OV 包含 32/16 两尺度的单通道 `soft_change/confidence` 和 8 通道 `relation`；SAMStruct 包含 T1/T2 的 256×256 `instance_id/boundary/quality`。**它们不是原始 DINOv2/SAM 特征库。** 若 relation 的通道对应有方向的邻接关系，flip、rotation、时相交换可能还需要通道置换或端点有效性处理；这只是需要向生成代码核验的条件，不能凭“8 通道”直接断定其语义。两时相实例 ID 也不能直接相减或按数值相等认定同一对象。

按上传的 Cache 说明，现有两类完整训练缓存覆盖 SYSU 与 WHU；不能由此推断 CDD、LEVIR 或 val/test 也有 Cache。以上是文档与公开代码审阅，没有重新登录服务器验证存量。

### 读完源码后，四个仍须补写的接口

下面是本项目的设计建议，**不是上述论文中已经存在的函数**。

| 待实现接口 | 应明确的输入 / 输出与问题 | 不可用什么替代 |
|---|---|---|
| `build_cd_difficulty()` | 输入停止梯度的学生预测与训练 GT；输出 `[B,6]` 的 h，并保留边界、内部、小连通域、背景等困难区域掩码 | 只用整图 entropy 无法区分漏检与误报；内部 FN 比率也不等于 fragmentation，后者需连通性/碎片统计；无变化或无小目标样本需定义有效标记 |
| `estimate_teacher_fit()` | 在同一困难区域，分别组织 teacher 自身 q 与困难适配 d；结构 teacher 用结构/关系证据，响应 teacher 才能直接比较变化响应与 GT | 不能对没有变化概率的 SAM instance ID 计算 teacher BCE；teacher–student gap 大也不能直接解释为 teacher 更可靠 |
| `route_teachers()` | h、q、d → 极小两层 MLP → `[B,K+1]` 概率；明确以“教师”为动作，多个尺度/损失属于该教师内部 | 不能把 SAM boundary、instance、quality 三个字段直接称作三个独立 teacher；quality 通常是可靠性输入而非要模仿的预测目标 |
| `reduce_teacher_losses()` | 各分支先得到 `[B,K]`；Reject 对全部教师项统一置零，GT 主监督照常；保留有效像素归一化 | 全局标量 auxiliary weight、只屏蔽 soft-change、按剩余 teacher 权重重归一化，都不能自动满足你的 Reject 定义 |

**Reject 还有两个必须写清的数学细节，任何一篇现成源码都不能替你决定：**

1. **K+1 softmax 本身只是软抑制，不会在有限 logits 下使 teacher loss 精确为 0。** 如果要求“选中 Reject 时只保留 GT”，需明确硬决定，例如 Reject 为 argmax 时统一关掉教师项，其余样本继续用教师权重；也可以另设明确的接受阈值。硬决定的训练方法要另外说明，不能把不可导 argmax 当作普通可导 softmax。
2. **不能让 router 只靠最小化它自己加权的非负蒸馏损失来学习。** 对固定学生，若目标只是

   $$L=L_{GT}+\lambda\sum_{k=1}^{K}w_kL_k,\qquad L_k\ge0,$$

   而 Reject 的损失为 0，那么把概率全部移向 Reject 就能减小该目标；这不是学会识别坏教师。可采用来自训练集内部的教师适用性监督，或基于独立训练子集上 GT 改善的效用目标，再监督 MLP；仅有“teacher loss 更小”不是可靠的效用标签。DynaKD 的双层优化和 MTKD-RL 的学生表现反馈值得读论文，目的就在这里，**并不要求你引入 RL**。

若采用分开训练 router 的实现，学生更新时可 detach h、q、d 的统计输入及路由权重，保留学生预测/辅助头到教师 loss 的梯度；router 在它自己的目标上反传。**如果照搬 UNIC 把权重 detach，却没有另一条 router 训练路径，MLP 就不会学。** 若改用可微双层目标，则应明确保留哪些高阶梯度，不能照抄这一 detach 方案。

## 4. 撞车风险提醒

**在本次核验的 16 篇论文与可用代码中，没有确认到完整实现“六类 CD 困难画像＋SAMStruct/OVCDistill 适配估计＋非 RL 小 MLP＋显式 Reject”的同构方法。这个结论只限定于本次材料，不能据此宣称全球首创。** 更现实的风险是：若只在通用多教师加权前加几个统计量，再把零权重称为 Reject，很容易被认为是已有机制的任务化拼接。

### 4.1 最高优先级边界：MTKD-RL 已经“不只相信 teacher confidence”

全文 Eq. (5) 的状态已经包含 teacher feature、logits、teacher 对 GT 的 CE、teacher–student feature cosine、probability KL；Action 使用线性层、ReLU 和 softmax，输出随输入样本变化的连续权重，随后用学生表现反馈训练策略。

因此，以下表述**不能独立作为新贡献**：“使用 GT 判断教师”“结合教师与学生差异”“按样本动态加权”“MLP＋softmax”。将 RL 换成普通梯度训练可以降低工程复杂度，但不自动构成方法新颖性。

你需要证明的差异是：**按漏边界、内部碎裂、小变化、背景误报等错误类型，识别某位异构教师是否能提供该错误需要的证据**；d 应体现这种有条件的适用性，而非换名后的 teacher CE/KL。读它主要为了划边界，本阶段仍不需要其 RL 源码。

### 4.2 Reject 的直接近邻：Re-DTS 已对每个教师定义“选 / 不选”

Re-DTS 的 Eq. (9) 为每位 teacher 设置二值动作；Algorithm 2 对所选集合 K 累加 soft loss，再加 hard loss。**从论文公式推断，若各动作都为 0，选中集合可以为空，教师损失可为 0。** 论文所示算法未写“至少选一个”的兜底；公开仓库未提供对应训练实现，所以这里是公式层面的推断，不能声称已经核验代码确实执行了全拒绝。

你的显式 K+1 Reject 与独立 Bernoulli 选择的参数化不同，但“允许不用任何 teacher、保留 GT”本身不足以与它划清边界。更强的区别应是：**何种 CD 困难与教师不适配触发拒绝，如何用非 RL 目标学会它，以及拒绝是否确实避免负迁移。**

### 4.3 UNIC 与 U-Know-DiffPAN：正是需要读源码来防止“改名复现”的两篇

| 工作 | 已有机制 | 你的区别必须落在哪里 |
|---|---|---|
| UNIC | 按样本丢 teacher，教师独立训练头，学生部署时不必保留全部训练结构 | 不能只是将随机 dropping 换成 MLP；要体现 GT 定义的错误类型、可靠适配而非最大模仿损失，以及允许拒绝所有教师 |
| U-Know-DiffPAN | 用不确定性在 GT 与 teacher 输出监督之间分配强度，且有离线蒸馏缓存 | 不能只是 `confidence × KD loss`；要有多位异构教师的困难适配比较，且 Reject 统一覆盖全部教师损失、GT 配方保持一致 |

### 4.4 GoodSAM、SemiCD-VL 与 BFD：论文必须读，源码无需等

- **GoodSAM：** 已经做结构/语义互补、区域自适应可信融合和边界改进，不能宣称“第一次利用 SAM 质量判断指导学生”；但其 Eq. (5) 是基础 CE 叠加高置信 mask 加权 CE，mask 为 0 时基础项仍在，不能把 MKA 说成你的全教师 Reject。
- **SemiCD-VL：** 已利用可信伪标签筛选及辅助分支缓解不可靠监督；“过滤低置信区域”“训练期辅助、推理不需要 VLM”不是独占特点，你的边界是全监督下、面向学生具体错误的多教师选择与拒绝。
- **BFD：** 与你的任务最接近的已有论点是 Foundation Model 给 CD 学生提供训练帮助、推理无额外负担；因此“训练用 FM、部署删干净、主网络轻量”应当作为设计约束和工程性质，而非单独的新颖性依据。

### 4.5 Mask-CDKD 的 gate 不等于你的 router

本次只为排除概念混淆，定点核对了官方代码的 [`teacher_sam_vit_mmoa.py`](https://github.com/whujader/mask_cdkd/blob/main/teacher_sam_vit_mmoa.py)：`MoAGate` 的 3 路对应 FFN＋两个 adapter；[`mask_cdkd_distiller.py`](https://github.com/whujader/mask_cdkd/blob/main/mask_cdkd_distiller.py) 则明确让教师适配部分保留梯度以做双向蒸馏。**它不是 SAM / DINO / Reject 三动作，也不是离线冻结 teacher 下的可靠性选择。** 这些定点核验足以排除误归类，无需为落地当前方案通读整个仓库。

### 4.6 最需要保留的可证伪边界

如果论文要把“CD-specific difficulty-aware reliable routing”写成方法贡献，至少应能回答：**相同教师池、相同 GT 损失、相同训练 BN/数据协议下，按错误类型构造的 d 是否比 confidence-only 或一般 teacher–student gap 更能预测教师帮助；Reject 是否主要发生在教师有害/不适配的情形，而非因为 loss 最小化退化成全拒绝。**

这也是本清单只推荐“2 篇必读＋1 篇建议”的原因：已有源码足以提供损失、缓存和二时相证据接口；剩下的核心工作是给出并验证你的困难—适配—拒绝关系，继续搬入 RL、VLM 或新的 Foundation Model 架构并不能替代它。
